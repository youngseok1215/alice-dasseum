1서비스 개요 및 핵심 가치

다씀은 사용자가 이미 보유한 화장품, 영양제, 의약품(안약 포함), 생활용품을 사진 한 장으로 등록·관리하고, 새 제품을 사기 전에 AI로 동일하거나 유사한 보유 제품이 있는지 확인해 불필요한 중복 구매를 예방하는 모바일 서비스입니다. 개봉일과 사용기한을 함께 관리해 이미 가진 제품을 기한 내에 끝까지 사용하도록 돕습니다.

핵심 가치설명관련 기능
중복 구매 예방구매 직전에 보유 여부를 빠르게 확인해 같은 제품을 또 사지 않도록 합니다.구매 전 AI 중복 확인
쉬운 기록촬영만으로 제품 정보를 채우고, 사용자는 확인·수정만 합니다.AI 제품 사진 등록
끝까지 사용개봉일·사용기한 기준으로 먼저 쓸 제품을 알려주고, 다 쓴 제품은 기록으로 남깁니다.사용기한 관리, 사용 순서 추천, 다씀
성과 확인다 쓴 기록과 구매 보류 기록으로 소비 관리 성과를 보여줍니다.절약 효과 확인

2문제 정의 및 서비스 개발 배경

2.1 문제 정의

  • 보유 현황 파악이 어렵습니다. 화장품, 영양제, 상비약, 생활용품은 욕실·방·가방 등 여러 곳에 흩어져 있어 매장이나 쇼핑 앱에서 구매할 때 집에 같은 제품이 있는지 기억하기 어렵습니다.
  • 할인과 프로모션이 중복 구매를 부추깁니다. 1+1, 기획 세트, 샘플 증정 등으로 이미 있는 제품을 다시 사게 됩니다.
  • 개봉 후 사용기한을 놓칩니다. 화장품과 안약 등은 개봉 시점부터 사용 가능 기간이 줄어들지만 개봉일을 기록하는 사람은 드뭅니다.
  • 끝까지 쓰지 못하고 버립니다. 새 제품을 먼저 열어 기존 제품이 기한을 넘기고 폐기되는 일이 반복됩니다.

2.2 개발 배경

  • 20~30대 1인 가구, 대학생, 사회초년생은 생활 제품 구매를 스스로 관리하며 지출에 민감합니다.
  • 기존 가계부·재고 관리 앱은 수기 입력 부담이 커서 지속 사용이 어렵습니다. 사진 인식으로 입력 부담을 낮추는 것이 핵심 차별점입니다.
  • 등록 없이도 쓸 수 있는 구매 전 확인 기능을 별도 흐름으로 제공해 첫 사용 진입 장벽을 낮춥니다.
의약품·영양제 원칙. AI는 영양제와 의약품의 의학적 효능, 성분 간 대체 가능성, 복용 적합성을 판단하지 않습니다. 사용기한은 제품에 표기된 공식 사용기한 정보를 우선합니다. 중복 확인은 제품명·브랜드·카테고리 등 식별 정보의 일치 여부만 안내합니다.

4.2 비기능 요구사항

  • 속도: 구매 전 확인은 매장에서 쓰는 기능이므로 진입부터 결과까지 최소 탭 수로 구성합니다. 홈에서 1탭으로 진입합니다.
  • 신뢰: AI 결과는 항상 '확인 필요' 상태로 표시하고 사용자가 최종 결정합니다.
  • 안전: 의약품·영양제에 대해 효능, 대체, 복용 관련 문구를 생성하거나 노출하지 않습니다.
  • 접근성: 터치 영역 최소 44×44pt, 본문 대비 4.5:1 이상, 상태를 색상만으로 구분하지 않고 텍스트 라벨을 함께 표기합니다.
  • 개인정보: 카메라·사진·알림 권한은 기능 사용 시점에 요청합니다.

5핵심 기능별 상세 요구사항

F1. AI 제품 사진 등록 MVP

제품을 촬영하면 AI가 제품 정보를 인식하고, 사용자가 확인·수정한 뒤 보관함(내 물품)에 등록합니다.

ID요구사항
F1-01카메라 촬영 또는 앨범에서 사진 선택으로 등록을 시작한다.
F1-02AI는 제품명, 브랜드, 카테고리를 인식해 입력 폼에 미리 채운다. 사용기한 등 인식 가능한 추가 정보가 있으면 함께 채운다.
F1-03AI가 채운 필드는 'AI 인식' 표시를 하고, 모든 필드는 등록 전 수정할 수 있다.
F1-04인식 실패 또는 일부 실패 시 빈 필드를 직접 입력하도록 안내한다.
F1-05필수값: 제품명, 카테고리. 선택값: 브랜드, 개봉일, 사용기한, 메모.
F1-06등록 완료 시 내 물품에 추가되고 완료 토스트를 노출한다.
F1-07잔량 입력 및 잔량 퍼센트 필드는 제공하지 않는다.
F1-08 제안등록하려는 제품이 이미 보관함에 있으면 "이미 등록된 제품이 있어요" 안내 후 '그래도 등록' / '취소' 선택. 같은 제품 여러 개 보유를 허용할지 확정 필요.
F1-09 제안'개봉 후 사용기간'(예: 12개월) 선택 필드. 화장품 PAO 표기를 반영해 개봉일 기준 기한 계산에 사용.

카테고리 (기본값)

화장품 · 영양제 · 의약품 · 생활용품. 하위 분류(스킨케어, 메이크업 등)와 사용자 정의 카테고리는 제안입니다.

F2. 보유 제품 관리 MVP

ID요구사항
F2-01등록 제품을 카테고리 탭/칩으로 필터링해 목록으로 본다. 기본 '전체'.
F2-02목록 카드는 제품 이미지, 제품명, 브랜드, 카테고리, 사용기한 상태(D-day)를 표시한다.
F2-03카드를 선택하면 제품 상세로 이동해 상세 정보, 개봉일, 사용기한을 본다.
F2-04상세에서 정보 수정, 개봉일 기록, 다씀 처리, 삭제를 할 수 있다.
F2-05정렬: 사용기한 임박순(기본), 최근 등록순.
F2-06 제안보관함 내 검색, 개봉/미개봉 필터.

F3. 구매 전 AI 중복 확인 MVP

구매하려는 제품을 검색하거나 촬영하면 내 물품과 비교해 동일·유사 제품 보유 여부를 안내합니다. 제품 등록 흐름과 완전히 분리된 별도 기능이며, 확인한 제품은 보관함에 자동 등록되지 않습니다.

ID요구사항
F3-01입력 방식 2가지: 텍스트 검색(제품명/브랜드), 사진 촬영(앨범 선택 포함).
F3-02결과는 3단계로 안내한다: 동일 제품 있음 / 유사 제품 있음 / 보유 제품 없음.
F3-03동일·유사 결과에는 해당 보유 제품 카드(이미지, 제품명, 개봉 여부, 사용기한)를 함께 보여주고 상세로 이동할 수 있다.
F3-04결과 화면에서 '구매 보류' 버튼으로 보류 기록을 남긴다. 이 기록은 절약 효과(F7)에 반영된다.
F3-05영양제·의약품은 제품 식별 정보 기준의 일치만 안내하며, 성분·효능이 비슷하다는 판단이나 대체 권유 문구를 노출하지 않는다.
F3-06보관함이 비어 있어도 사용할 수 있으며, 이 경우 '보유 제품 없음'과 함께 등록 유도 문구를 보여준다.
F3-07 제안'유사'의 판단 기준: 같은 브랜드의 같은 라인(용량·리뉴얼 차이) 또는 같은 카테고리 내 같은 제품 유형(예: 선크림). 의약품·영양제는 '유사' 단계를 쓰지 않고 동일 여부만 안내하는 안 검토.
F3-08 제안결과 화면에서 '보관함에 등록' 바로가기(F1 흐름으로 정보 전달). 흐름 분리 원칙과 충돌하지 않도록 사용자가 명시적으로 선택할 때만 실행.

F4. 사용기한 관리 MVP

ID요구사항
F4-01제품별 개봉일과 사용기한을 저장·수정한다. 개봉일은 '오늘 개봉' 빠른 입력을 제공한다.
F4-02기한 상태를 4단계로 표시한다: 여유 / 임박 / 오늘까지 / 기한 지남. 사용기한 미입력 시 '기한 미입력'.
F4-03기한 임박 제품을 알림 목록과 푸시 알림으로 안내한다.
F4-04영양제·의약품은 제품에 표기된 공식 사용기한을 우선 기준으로 한다.
F4-05 제안임박 기준: 기본 D-30, 설정에서 D-7 / D-14 / D-30 / D-60 선택.
F4-06 제안실제 기준 기한 = min(표기 사용기한, 개봉일 + 개봉 후 사용기간). 의약품·영양제는 표기 사용기한만 사용.

F5. 다씀(사용 완료) MVP

ID요구사항
F5-01제품 상세에서 '다씀' 버튼을 누르면 확인 시트 후 사용 완료 처리한다.
F5-02완료된 제품은 내 물품 목록에서 빠지고 '다씀 기록'으로 이동한다. 완료일이 저장된다.
F5-03완료 직후 사용 완료 화면을 보여준다(마스코트 영역, 누적 다씀 개수).
F5-04실수 방지를 위해 완료 직후 스낵바 '실행 취소'를 제공한다.
F5-05 제안기한이 지나 사용하지 못하고 버린 경우를 '폐기'로 구분 기록. 절약 효과 해석에 영향이 있어 확정 필요.

F6. 사용 순서 추천 MVP

ID요구사항
F6-01개봉일과 사용기한을 기준으로 먼저 확인해야 할 제품을 홈에 노출한다.
F6-02기본 정렬 규칙: ① 기한 지남 ② 사용기한 임박순 ③ 같은 기한이면 개봉 제품 우선 ④ 개봉일이 오래된 순.
F6-03같은 카테고리에 개봉 제품이 여러 개면 "이것부터 써 보세요" 형태로 안내한다.

6.2 주요 흐름

A. 첫 실행

앱 실행 → 온보딩(서비스 소개 3장) → 시작하기 → 홈(빈 상태) → '첫 제품 등록' 또는 '구매 전 확인 해보기'

B. 제품 등록

홈/내 물품 '등록' → 카메라 권한 확인 → 촬영(또는 앨범) → AI 인식 중 → 정보 확인·수정 → 등록 → 완료 토스트 → 내 물품(신규 제품 강조) 또는 이전 화면
└ 인식 실패 → 직접 입력 폼 / 다시 촬영

C. 구매 전 중복 확인 (등록과 별도)

구매 전 확인 탭 → 검색 입력 또는 촬영 → AI 확인 중 → AI 확인 결과
├ 동일 제품 있음 → 보유 제품 카드 → [구매 보류] → 보류 기록 저장 → 완료 안내 / [제품 상세 보기]
├ 유사 제품 있음 → 유사 제품 목록 → [구매 보류] / [그래도 구매할게요]
└ 보유 제품 없음 → [다시 확인] / [확인 종료]

D. 사용기한 관리

푸시 알림 탭 또는 홈 알림 아이콘 → 사용기한 알림 목록 → 제품 선택 → 제품 상세 → 다씀 / 개봉일 기록 / 사용기한 수정

E. 다씀 처리

제품 상세 → [다씀] → 확인 시트 → 사용 완료 화면 → 홈 또는 내 물품으로 복귀 (스낵바 '실행 취소')

9.1 UX 원칙

  • 판단은 사용자에게. AI 결과는 제안으로 표현합니다. "이미 가지고 있어요", "확인해 주세요"처럼 단정·명령 대신 안내형 문구를 씁니다.
  • 친근하되 유치하지 않게. 해요체를 쓰고, 감탄사·과도한 이모지·과장 표현을 쓰지 않습니다. 마스코트가 정서적 역할을 맡고 UI 문구는 간결하게 둡니다.
  • 죄책감 대신 성과. 기한 지남, 중복 구매 상황에서 사용자를 탓하는 문구를 쓰지 않습니다.
  • 매장에서 한 손으로. 구매 전 확인의 주요 버튼은 하단 엄지 영역에 둡니다.
  • 색만으로 상태 구분 금지. D-day 배지는 색 + 텍스트를 함께 씁니다.

10브랜드 디자인 가이드

v0.2 변경 범위. 서비스 기능과 사용자 흐름은 v0.1과 같습니다. 이 장(브랜드 컬러, 마스코트)과 이를 참조하는 화면별 마스코트 표기만 바뀌었습니다.

10.1 적용 원칙

  • Wanted Design System 우선. 컴포넌트, 타이포그래피, 간격, radius, 인터랙션 상태는 Wanted DS를 그대로 사용합니다.
  • 브랜드는 토큰으로만 적용. 다씀 컬러는 Wanted DS의 Primary·Background 변수를 덮어써서 적용하며, 색을 바꾸기 위해 컴포넌트를 새로 만들지 않습니다.
  • 마스코트는 이미지 자산. 마스코트는 컴포넌트가 아니라 지정 화면에만 들어가는 공식 이미지입니다. Wanted DS의 Thumbnail(이미지 슬롯) 위에 배치합니다.
  • 민트는 절제해서. 화면 대부분은 배경색·화이트·크림으로 두고, 민트는 화면당 주요 행동과 강조 요소에만 씁니다.

  • #D9EFE9 카드는 한 화면에 1~2개만 씁니다. 목록형 카드는 화이트 카드로 둡니다.
  • 크림(#F2EDE5)은 정보 영역을 묶거나 쉬어 가는 영역에 쓰고, 민트 영역과 맞붙이지 않습니다.
  • 여백은 Wanted DS 간격(좌우 20px, 섹션 간 28~40px)을 넉넉하게 적용합니다.

자산 규격

확인 필요. 첨부 이미지는 흰 배경이 포함된 불투명 PNG 1장(1191×454)에 3종이 함께 있습니다. 배경 #F7FAF8 위에 놓으면 흰 사각형이 보이므로 버전별 투명 배경 PNG 원본(@2x·@3x, 최소 720×720)이 필요합니다. 기본 미소 버전(A)도 돋보기를 들고 있습니다. 돋보기 없는 기본 버전이 필요하면 원작자에게 요청하며, AI로 지우거나 수정하지 않습니다.

파일명 제안 mascot_smile · mascot_search · mascot_done (@2x, @3x). 이 문서의 이미지는 첨부 원본을 버전별로 잘라 참고용으로만 넣었습니다.
